## 📊 КАК ЭТО РАБОТАЕТ

### Архитектура WB Engine:

```
Запрос товара
    ↓
WBEngine.get_product(article)
    ↓
Пробует источники по приоритету:
    1. SellerAPISource (priority=0) → не настроен, пропускается
    2. CDNSource (priority=10) → получает контент, но Detail API → 403
    3. SearchFallbackSource (priority=20) → ✅ РАБОТАЕТ!
       └─> search.wb.ru/exactmatch
           └─> Возвращает товар с ценами
               └─> apply_detail() извлекает цены
    4. HistoryFallbackSource (priority=100) → если все провалились
    ↓
Возвращает WBProduct с ценами
```

### Почему SearchFallbackSource работает:

1. **Использует search API вместо detail API**
   - search.wb.ru менее защищен чем card.wb.ru
   - Блокируется реже (429 вместо 403)

2. **Search API возвращает тот же формат данных**
   ```json
   {
     "products": [
       {
         "id": 211246754,
         "name": "...",
         "reviewRating": 4.8,
         "feedbacks": 1234,
         "sizes": [
           {
             "price": {
               "basic": 299900,   // старая цена в копейках
               "product": 199900  // финальная цена в копейках
             }
           }
         ]
       }
     ]
   }
   ```

3. **apply_detail() одинаково обрабатывает оба источника**
   - Извлекает reviewRating → product.rating
   - Извлекает feedbacks → product.feedbacks
   - Извлекает sizes[].price.basic → product.old_price
   - Извлекает sizes[].price.product → product.price
   - Рассчитывает скидку

## ❓ FAQ

### Q: Почему раньше цены не работали?

**A:** Потому что:
1. CDNSource пытался использовать Detail API → 403
2. SearchFallbackSource был с priority=20 (низкий приоритет)
3. IP быстро блокировался из-за частых запросов
4. Прокси не работал

Теперь когда CDNSource получает 403, WBEngine автоматически переходит к SearchFallbackSource, который работает.

### Q: А если search API тоже заблокируется?

**A:** Тогда:
1. WBEngine перейдет к HistoryFallbackSource
2. Вернет последние известные данные из памяти ARGUS
3. С пометкой `source="history"`
4. Лучше показать старую цену, чем ничего

### Q: Можно ли вообще не использовать прокси?

**A:** Можно, но:
- ✅ Для разработки / тестирования
- ❌ Для production
- ⚠️ WB быстро заблокирует IP при частых запросах

### Q: Какой прокси лучше?

**A:** Для e-commerce парсинга:
1. **Residential прокси** (лучший выбор)
   - Настоящие IP обычных пользователей
   - WB не может отличить от реального трафика
   - Дорого, но надежно

2. **Mobile прокси** (альтернатива)
   - IP мобильных операторов
   - Тоже хорошо для WB
   - Средняя цена

3. **Datacenter прокси** (НЕ рекомендуется)
   - Дешево
   - WB легко их блокирует

### Q: Сколько прокси нужно?

**A:** Зависит от нагрузки:
- **1-10 запросов/мин**: 1-2 прокси
- **10-100 запросов/мин**: 5-10 прокси
- **100+ запросов/мин**: 10-50+ прокси

ProxyPool автоматически ротирует их.
